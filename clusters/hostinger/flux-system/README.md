# Flux bootstrap — `flux-system`

**This directory is applied once, by hand, and is not reconciled by Flux itself.**

Flux cannot install itself: something has to create the controllers that then watch Git. That
bootstrap is the one manual `kubectl apply` in this repository, and everything after it is
reconciled from `main`. Committing the manifest *before* applying it is what makes even the
bootstrap reviewable — the file below is the exact bytes that were applied, not a description
of them.

## What is installed, and what is not

**Two controllers, and no more:**

| Component | Image (digest-pinned) |
|---|---|
| `source-controller` | `ghcr.io/fluxcd/source-controller:v1.9.4@sha256:8a8ed0a5…` |
| `kustomize-controller` | `ghcr.io/fluxcd/kustomize-controller:v1.9.4@sha256:2b8bec54…` |

Both are pinned by **digest**, not by tag, for the same reason the application is: a tag can be
repointed, and a controller that can change without a commit is a controller nobody is
reviewing.

**Deliberately absent:** `helm-controller`, `notification-controller`,
`image-reflector-controller`, `image-automation-controller`. Renvor deploys plain Kustomize
manifests from a public Git repository. `image-automation-controller` in particular would be
actively wrong here — it writes commits back to Git, which would need a credential this
deployment does not have and must not acquire.

*(Names such as `helm-controller` do appear inside the RBAC rules and CRD definitions in the
manifest. Those are grants and schemas, not workloads: the file contains exactly two
Deployments, which `grep -c '^kind: Deployment'` confirms.)*

**Contents:** 7 CustomResourceDefinitions (source and kustomize toolkits only), 2 Deployments,
2 ServiceAccounts, 3 ClusterRoles, 2 ClusterRoleBindings, 1 Service, 3 NetworkPolicies, and 1
ResourceQuota — all in `flux-system`.

## What it is allowed to reach

- **One source:** the **public** `https://github.com/renvor-rs/renvor-infra` over HTTPS, with
  **no credential of any kind** — no deploy key, no PAT, no `secretRef`. The repository is
  public, so anonymous read is sufficient, and there is nothing to rotate or leak.
- **One path:** `clusters/hostinger`. Nothing else in the repository is reconciled.
- **Renvor namespaces only.** The Kustomizations name `renvor-site-staging` and `renvor-site`.
  Flux is never pointed at `gitlab`, `attaa`, `codexhub`, `portfolio`, or `kube-system`.

## Applying it

```sh
kubectl apply --server-side -f clusters/hostinger/flux-system/flux-system.yaml
kubectl -n flux-system rollout status deploy/source-controller deploy/kustomize-controller
```

`--server-side` because the CRDs in this file exceed the annotation size limit that
client-side apply uses to store its last-applied state.

## Removing it

```sh
kubectl delete -f clusters/hostinger/flux-system/flux-system.yaml
```

This removes the controllers and the Flux CRDs. It does **not** remove the workloads Flux
created — deleting the Renvor Kustomizations first, and letting pruning run, is the ordered way
to do that. See `docs/runbooks/rollback.md`.
